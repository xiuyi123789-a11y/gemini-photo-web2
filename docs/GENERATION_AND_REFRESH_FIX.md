# 生成入口与刷新展示修复（2026-11-10）

## 用户涂抹决定范围

图像复刻的 `user-brush` 模式不再要求涂抹命中 AI 定位框，也不再要求额外勾选定位差异确认。后端用完整尺寸的涂抹图验证非空，区域指引保留全部涂抹。定位框缺失、越界时保留有效的产品分析，框记为 null，不阻断用户选择。旧版 adaptive 模式仍保留自身的实例校验。

涂抹采样网格根据最小笔画自适应，修复 2048×2048 图片使用 0.005 画笔点选时实际有约80个像素、旧192网格却判为空的问题。完全擦除、无效素材、账号隔离、素材绑定与请求去重保持有效。

## v1.5.8：默认直接生成

- 上传场景与产品参考后即可涂抹生成。辅助识别为可选的独立收费动作；直接生成先通过 `/materials` 本地保存与规范化图片，不调用文字模型。
- AI 返回缺字段、截断 JSON、定位不明确，均转为提示和可用特征；无法确认的细节以参考图为准，不编造。历史失败分析也可复用已保存素材。
- 取消费用勾选框，按钮旁明确展示本次张数及计费提示。空摘要自动使用图片指导；长摘要自动限制到可用长度。
- 新的明确点击可以新建任务，旧的未知提交保持原状态与记录；同一个请求或预测尝试仍不可重复提交。PostgreSQL 初始化会删除旧的账号单任务/单收件唯一索引，保留请求 ID 和预测尝试唯一约束。
- 不再用历史未结束记录数量作为全站 20 个任务的准入门槛。工作台展示当前账号的未结束任务，查询和取消不影响当前素材。
- 现存的已保存素材不因分析时间戳过期而拒绝读取；新素材保留，历史依赖素材随已保留结果保留。刷新恢复未提交的笔画、要求与设置；修改参考角度后可复用服务端图片，无需用户重新上传。
- 细小涂抹以至少 1 个有效像素为准；完全擦除仍不能生成。4K 和多张输出向直接生成开放。
- 图片可解码、格式/体积/像素资源边界、原图与涂抹坐标一致、账号认证以及供应商本身的可用性仍按实际条件处理。该改动不绕过供应商错误或服务端关闭开关。

## 首页首次发送

原首页首次发送仅写入聊天记录并进入画布，没有启动需求理解或生成。现在完成素材载入后只启动一次生成流程。首页和画布输入区均显示风格与比例选项，默认产品摄影 / 3:4，可修改；选项按账号保存。缺项直接在输入区提示，后端也验证明确选项，缺项不调用模型。模型再次追问已选风格或比例时使用用户已提交的明确需求继续；其他追问与失败仍清楚显示并保留输入。

## 图片展现顺序

旧链路存在隐藏页面一起挂载和请求、先下载完整原图获取画布尺寸、直接等待大预览/原图才能显示等成本。此前已有私有HTTP缓存与服务端预览缓存，本次是在此基础上调整展示顺序：

1. 登录核验后只加载当前页面；其他板块首次访问才加载。
2. 已保存的结果/画布可先回显；收费任务状态仍独立核对。
3. 384像素 WebP 小预览先显示，然后后台加载并切换1024/1600像素预览；清晰预览失败时保留小图。
4. 首次请求预览时生成并持久缓存，复刻素材和结果保存时预备小预览；有效304无需重新生成预览。
5. 图片尺寸通过经同样权限验证的 `metadata=1` JSON读取，不先下载原图；放大窗口提供“查看完整原图”，下载保持完整原图。

- TypeScript检查及Vite生产构建通过。

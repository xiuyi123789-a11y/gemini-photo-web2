# 图像复刻提交与恢复修复验收

## v1.5.3：费用确认、刷新速度与结果恢复（2026-10-28）

基线 `bd8df8123a4d8ac085ad7114a1cad7c1f39beee3`。截图显示生产界面为 v1.5.1；本轮修复在正式项目源码及本地工作台验证，不修改生产服务，不新增真实收费预测。

已确认的代码问题与修复：

1. `ImageReplicationView` 的费用 checkbox 复用 `generationReady`，其中包含涂抹与定位框匹配判断，导致识别成功但涂抹不匹配时无法勾选。现拆分费用确认与生成准入；按钮仍校验分析、替换范围、运行中任务及费用确认。纯背景涂抹不会因此启动生图，范围不匹配会显示明确原因。
2. 鼠标悬停也重算整个涂抹栅格；刷新先等 IndexedDB、重复读任务，所有图片还反复加载完整PNG。现缓存涂抹匹配、合并并行相同GET、只读查询最多等待15秒、数据库草稿读取最多1.5秒；侧栏使用384边长缩略图，画布使用1600边长预览，保留原始坐标和比例。放大查看与下载仍读取完整PNG，存储像素及模型输出不改。图片使用经账号验证的private条件缓存，命中后304；身份验证发生在304之前，不做公共缓存。
3. 页面只靠浏览器任务标记找结果，服务端 `/active` 不返回已完成任务；恢复新旧任务时还会争用当前素材上下文。现增加只读 `/workbench`，按当前账号、最新素材指纹及分析/生成关联恢复，先确定素材，再恢复分析和结果；旧请求标记需确认终态后才能替换，404仍保留费用保护。生成结果加载失败不会换成原图，新增“重新加载图片”，只刷新资源。
4. worker曾把供应商已成功后的下载中断标为终态 `quality_failed / OUTPUT_INVALID`，无法继续取回。现在网络下载中断停在可恢复状态，保留原预测ID，显式重新连接只查询同一ID并下载。对历史同类终态，只有已记录成功的Nano Banana 2预测、无结果、账号一致且无其他活动任务时，才允许“取回已生成图片”。恢复使用 `resumeOnly`，不能创建替代预测或追加批次；取回仍失败时可停止等待，已付费记录保留。

### 边界与回滚

截图中的断图证明资源加载失败，不能单凭截图断言服务器文件已删除或网络“丢包”。本轮未能连接生产浏览器调试会话，因此没有拿到该次生产图片HTTP状态；本地复现并修复的是上述可确认的状态、恢复及下载缺陷。供应商下载地址已过期、磁盘文件实际丢失或持续网络故障，不能承诺凭空恢复；不会为此自动重新生成收费图片。

本轮不改模型或提示词，不变更数据库结构，不清理用户任务或图片。回滚以 `git revert <本次修复提交SHA>` 创建新提交，按固定SHA发布；回退基线为上文bd8df81。先处理恢复中的任务至终态，保留预测ID、素材及费用保护记录；不能通过删除任务或重复付费提交“回滚”。腾讯云需部署该版本后才能使用这些修复。

## 2026-10-26 上传规范化修复历史

日期：2026-10-26。本地基线：`c126a47c7be22d6cd700168af4097616858a7f38`。修复分支：`codex/replication-upload-normalization`。本轮未上传 GitHub、未部署生产、未调用真实模型。

## 已确认原因

1. 用户上传的场景 WebP 和四张 JPEG 参考图合计 **31,170,410 字节（29.7 MiB）**，符合原文件合计 32 MiB 的限制，素材没有丢失。
2. `server/replication-assets.js` 的 `prepare()` 将高清 JPEG 无损转成 PNG 后，再套用上传大小限制。前两张参考图转换后分别为 **19,651,438** 和 **14,807,814** 字节，仅这两张合计 **34,459,252** 字节就超过内部 32 MiB 上限，因此在创建 job 和模型 attempt 前失败。
3. `services/replicationService.ts` 的 `submit()` 查询到后端已封存的受理回执后，用通用 `REQUEST_CLOSED` 覆盖了原始 HTTP 错误，页面只显示“本次素材提交未完成”。

本地现有记录中对应的三次失败请求均为 `closed`、`jobId: null`，没有模型 attempt。原始图片与取证脚本保存在项目忽略目录 `.local/migration-archive/upload-intake-2026-10-26/`，不进入源码或 Git。

## 最小修复

- 原始上传大小及像素上限不变。按 EXIF 校正、sRGB 规范化后的完整场景保存为 `source.png`，用于涂抹坐标和最终合成，不再因 PNG 编码膨胀而误拒合法上传。
- 单独限制模型输入副本：单图最多 20 MiB、场景加产品参考合计最多 32 MiB；参考图最长边不超过 3072，并按剩余预算继续等比缩小。仅当场景 PNG 超过单图预算时才增加 `model-source.png`，完整场景始终保留。禁止多帧素材，防止帧信息丢失造成错误输入。
- worker 选择模型场景副本；生成任务克隆、私有素材读取一并支持该副本。场景坐标和最终合成继续使用完整 `source.png`。生成的区域指引图单独附加，仍按既有规则最长边 1536。
- 后端安全封存流程不变，增加不含素材或凭据的处理失败日志。客户端在确认封存后保留原始 HTTP 错误；只有无确定 HTTP 响应时才使用通用安全结束提示。队列繁忙、图片处理失败等原因不再被覆盖。
- 模型、分析和生成提示词、GET 只读、原子封存、未知费用保护及显式生成规则均未改变。不自动重提任务。

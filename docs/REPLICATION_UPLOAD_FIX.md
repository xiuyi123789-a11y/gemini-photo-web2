# 图像复刻上传后“提交未完成”修复验收

日期：2026-10-26。本地基线：`c126a47c7be22d6cd700168af4097616858a7f38`。修复分支：`codex/replication-upload-normalization`。本轮未上传 GitHub、未部署生产、未调用真实模型。

## 已确认原因

1. 用户上传的场景 WebP 和四张 JPEG 参考图合计 **31,170,410 字节（29.7 MiB）**，符合原文件合计 32 MiB 的限制，素材没有丢失。
2. `server/replication-assets.js` 的 `prepare()` 将高清 JPEG 无损转成 PNG 后，再套用上传大小限制。前两张参考图转换后分别为 **19,651,438** 和 **14,807,814** 字节，仅这两张合计 **34,459,252** 字节就超过内部 32 MiB 上限，因此在创建 job 和模型 attempt 前失败。
3. `services/replicationService.ts` 的 `submit()` 查询到后端已封存的受理回执后，用通用 `REQUEST_CLOSED` 覆盖了原始 HTTP 错误，页面只显示“本次素材提交未完成”。

本地现有记录中对应的三次失败请求均为 `closed`、`jobId: null`，没有模型 attempt。原始图片与取证脚本保存在项目忽略目录 `.local/migration-archive/upload-intake-2026-10-26/`，不进入源码或 Git。

## 最小修复

- 原始上传大小及像素上限不变。按 EXIF 校正、sRGB 规范化后的完整场景保存为 `source.png`，用于涂抹坐标和最终合成，不再因 PNG 编码膨胀而误拒合法上传。
- 单独限制模型输入副本：单图最多 20 MiB、场景加产品参考合计最多 32 MiB；参考图最长边不超过 3072，并按剩余预算继续等比缩小。仅当场景 PNG 超过单图预算时才增加 `model-source.png`，完整场景始终保留。禁止多帧素材，防止帧信息丢失造成错误输入。
- worker 选择模型场景副本；生成任务克隆、私有素材读取一并支持该副本。场景坐标和最终合成继续使用完整 `source.png`。生成的区域指引图单独附加，仍按既有规则最长边 1536。
- 后端安全封存流程不变，增加不含素材或凭据的处理失败日志。客户端在确认封存后保留原始 HTTP 错误；只有无确定 HTTP 响应时才使用通用安全结束提示。队列繁忙、图片处理失败等原因不再被覆盖。
- 模型、分析和生成提示词、GET 只读、原子封存、未知费用保护及显式生成规则均未改变。不自动重提任务。

## 验收结果

- 同一组用户原图原样复测：5 张全部接收，模型输入合计 **22,393,188 字节（21.4 MiB）**。四张参考图均为 3072×2048；场景保持 **1080×1440**，规范化解码后的每个像素与修复前预期原图一致。
- 同一组素材浏览器测试：显式点击识别 → 受理成功 → 分析完成并回填 → 按钮恢复可操作。新增 **1 次 Mock 分析、0 次 Mock 生图、0 次真实模型调用**。Mock 返回固定示例，不代表真实 AI 识别准确率。
- `npm test`：**72/72 通过**。新增合成高熵 JPEG 回归，先断言 PNG 膨胀超过旧上限，再验证合法素材成功受理、模型副本预算、完整场景、worker 输入顺序、克隆及私有访问；新增素材处理失败与页面错误保留、素材可复用回归。既有请求中断、404、刷新、重复提交、旧生图任务误唤醒、服务重启及其他板块 Mock 均通过。
- `npm run typecheck`、`npm run build`、`git diff --check` 通过。

主要改动：`server/replication-assets.js`、`server/replication-worker.js`、`server/replication.js`、`services/replicationService.ts`、`shared/replication-contract.js`、`tests/replication.test.js`、`tests/replication-ui.test.js`。

## 剩余边界与回滚

模型副本缩放可能影响极小文字或细节，需要后续在获准的真实模型验收中确认；本轮只验证提交、图片处理和回填链路。完整场景解码/保存仍占用内存和磁盘，未更改既有像素上限或做队列架构重构。

生产未改变，无需生产回滚。新格式对旧任务兼容，但旧 worker 不理解新增的 `inferenceSource`，因此不得让旧代码恢复尚未结束的新格式任务。若撤回本地修复，应先让新任务进入终态、保留素材与任务记录，再回到上述本地基线；不能通过删除受理回执或重提付费任务“恢复”。

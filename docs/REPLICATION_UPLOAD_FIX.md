## v1.5.6：下载与图片刷新性能（2026-10-29）

基线 `bcc9e827ab1aa1560d2a38768c7fa08d739a68a1`。用户确认刷新后已能看到真实生成图，但下载无反应。本轮按要求跳过云端文件探测，复用已有结果验证下载；不调用真实收费模型，不修改已有任务、图片或数据库结构。

### 已确认的问题与修改

- `ImageReplicationView.download` 原先先等待完整图片 fetch/blob，再点击未挂入文档的链接；等待8 MB级文件时无反馈，也没有明确的服务端附件响应。`GenerationView` 同样先等待完整下载并立即回收blob。现由 `services/imageDelivery.ts` 在原点击事件内同步挂载、点击链接，服务器返回 `Content-Disposition: attachment`，直接流式传输完整原图，支持Content-Length和Range。页面提示“已发起下载”，不会误称浏览器已经保存完成。HomeView及SmartRetouchView统一使用此入口。
- 普通 `/api/images` 图片继承全局API `no-store`，复刻图片每次强制重新验证；多个板块又使用完整PNG做小图。现在 `server/image-delivery.js` 统一提供384缩略图、1024展示图、1600画布预览（WebP）；放大窗口与下载仍读完整原图。源文件保持不变。
- 复刻图片URL在DTO层带原文件hash版本号，普通图片按不可变UUID文件名识别。版本化响应使用 `private,max-age=3600,immutable` 并 `Vary: Cookie,x-user-id`；非版本化旧URL继续重新验证；下载和显式重载为no-store。所有到服务器的请求仍先鉴权、核对所属账号，再处理缓存验证与文件流。没有公共缓存或URL凭据。
- 原复刻缩略图仅内存保存24项，进程重启或大量素材会重复转换。现在派生预览持久保存在用户数据目录的 `previews/` 中，同一内容/规格并发请求合并，Sharp转换最多同时2个；相同内容跨任务可复用，失败转换不留下半成品。
- `ImageReplicationView` 原先等待任务查询后才挂载图片。现在账号隔离的localStorage只保存最近完成图片的少量展示元数据（最大128 KiB、24小时、仅私有本地图片URL），先回显，再GET核对。不缓存图片base64、Token、任务执行状态、涂抹或费用同意。空快照或新素材上下文移除旧结果；服务器状态恢复前不能凭缓存开始生成。workbench/active数据库查询改为先按账号筛选；增加Server-Timing便于后续区分接口与文件耗时。

- 实际点击“下载图片”触发浏览器download事件，文件落盘8,648,887字节，SHA256为 `3315b05c337d224c50a51a2687dbcfc2bf02b0f124f9d421796a9e1c0c58d750`，与已有原图一致。浏览器临时下载文件已移入项目私有验收目录。
- 缓存刷新时，场景缩略图116.2 ms、参考和结果116.4 ms加载完成，三张图片transferSize均为0。故意延迟的workbench请求实际耗时2507 ms，未挡住图片回显。1600预览728,668字节，原PNG为8,648,887字节。这是本机暖缓存测量，不是腾讯云首开、大图下载或所有设备的延迟承诺。
- 全量Mock回归157/157通过，类型检查和生产构建通过。新增回归覆盖同步下载与附件原始字节、Range、预览不替代下载、跨账号/匿名访问、持久预览与重启、转换合并与并发上限、缓存先回显但费用锁不释放、权威空/新上下文、损坏或过期缓存。原有请求中断、未知提交、404恢复、重复点击、旧任务误唤醒、服务重启、原预测ID取回继续通过。

### 限制与回滚

## 已确认原因

1. 用户上传的场景 WebP 和四张 JPEG 参考图合计 **31,170,410 字节（29.7 MiB）**，符合原文件合计 32 MiB 的限制，素材没有丢失。
2. `server/replication-assets.js` 的 `prepare()` 将高清 JPEG 无损转成 PNG 后，再套用上传大小限制。前两张参考图转换后分别为 **19,651,438** 和 **14,807,814** 字节，仅这两张合计 **34,459,252** 字节就超过内部 32 MiB 上限，因此在创建 job 和模型 attempt 前失败。
3. `services/replicationService.ts` 的 `submit()` 查询到后端已封存的受理回执后，用通用 `REQUEST_CLOSED` 覆盖了原始 HTTP 错误，页面只显示“本次素材提交未完成”。

本地现有记录中对应的三次失败请求均为 `closed`、`jobId: null`，没有模型 attempt。原始图片与取证脚本保存在项目忽略目录 `.local/migration-archive/upload-intake-2026-10-26/`，不进入源码或 Git。

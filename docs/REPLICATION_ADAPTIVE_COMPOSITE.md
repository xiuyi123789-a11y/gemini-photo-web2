## 技术选择与实际能力

现有`server/replication-composite.js`原来直接把涂抹栅格用于合成，并对边界向内羽化。它不能理解新产品轮廓。本次彻底移除该回退路径。

本地推理候选经过评估：

| 方案 | 结论 |
| --- | --- |
| Node.js + Sharp | 负责像素、掩码存储、无损合成；没有语义分割能力，不能冒充主体识别 |
| OpenCV GrabCut | 免费CPU图割，但依赖前景/背景种子，近色、遮挡和复杂商品图需较多修正；不作为默认自动主体分割 |
| MobileSAM | 官方提供CPU推理；本次接入真实本地推理，不向供应商发送图片。适用于点提示分割，但不能保证商品级语义完整性，必须附带可靠性与人工审核 |
| SAM 2 | 需要独立PyTorch/模型运行环境；本轮不默认引入较大的服务依赖 |

依据：[MobileSAM官方仓库及CPU说明](https://github.com/ChaoningZhang/MobileSAM)、[OpenCV GrabCut官方说明](https://docs.opencv.org/4.x/d8/d83/tutorial_py_grabcut.html)、[SAM 2官方仓库](https://github.com/facebookresearch/sam2)。MobileSAM模型代码固定到`f706ad9c4eb7f219c00d9050e46328518ffb65d2`。没有采用固定扩大涂抹或像素差异阈值代替分割。

## 数据职责

所有结果坐标都以方向已校正的场景原图像素为准；原图与完整模型结果分别保存，互不覆盖。

| 数据 | 含义 | 用途 |
| --- | --- | --- |
| `selectionMask` | 从既有`input.brush`或历史多边形栅格得到的用户选择 | 选择实例、分割提示；绝不作为合成裁切边界 |
| `sourceObjectMask` | 按实例识别的原产品可见轮廓 | 完整移除原产品，识别新产品缩小时需恢复的区域 |
| `generatedObjectMask` | 在对齐后的模型图上识别的新产品轮廓 | 新产品完整拷贝区，允许超出用户涂抹 |
| `occlusionMask` | 原图袜子、裤脚、手等保护区域 | 原像素保留，覆盖层优先于产品；不能确认时停止合成 |
| `compositeMask` | 根据新旧轮廓、保护物、未选中实例及接缝自动计算 | 唯一最终合成区域 |

结果以`results[].compositeMasks`关联五张独立PNG资产，均受原有账号隔离检查。数据库保留资产描述、掩码校验值、实例指标和对齐证据；不保存大段base64或凭据。无需数据库结构迁移。

## 算法与失败条件

1. 持久保存场景原图、全部模型画面。新生成/本地重合成任务设置`retainOriginals`，普通到期清理不删除；保留到未来明确的用户删除操作。历史记录不批量修改。
2. 以全部实例框与用户选择提示MobileSAM识别原产品。框只是定位和分割提示，不是粘贴区域；分割也需考虑未选中产品，以保护其实际轮廓。
3. OpenCV ORB在产品之外提取背景特征，匹配后用RANSAC估计相似变换。必须有足够内点、跨至少三个网格的分布和低重投影误差。只允许很小的平移、旋转及等比校正；画面比例异常、较大偏移或缺少对应背景时停止。没有`fit:fill`式非等比拉伸。
4. 在已对齐模型图识别新产品，结合实例ID、重叠与几何关系逐一匹配。低置信度、低稳定性、部件级小掩码、相互冲突或错配时停止。模型有较高分数也不能单独证明完整主体正确。
5. 涉及遮挡的实例必须有可确认的前景保护；本轮会要求必要的遮挡点提示。用户可点产品内部、排除背景或点袜子/裤脚，重新运行本地分割，不需要描出最终尺寸。
6. 合成核心取新旧产品轮廓并集，扣除前景和未选中产品保护区。新产品比旧产品小时，旧轮廓减去新轮廓的区域采用模型已恢复背景；检查周围已知背景的一致性及旧像素残留，证据不足即停止。它不能恢复不可见背景的真实历史像素。
7. 核心区直接拷贝模型结果，alpha为1，不向鞋底、鞋头、Logo内部羽化。仅在实际轮廓之外1像素且背景匹配的接缝处混合。该接缝不是扩大用户选择来代替分割。
8. 可疑结果返回`buffer:null`，保留完整模型图、失败原因以及已有的诊断掩码。成功合成也只标记`completed_needs_review`；像素变化、掩码置信度均不能自动证明具体商品正确。

像素差异仅用于背景恢复/残留和几乎未变化的检查，不负责识别主体。复杂接触阴影、透明物体、细链条、镜面反射和精细发丝不保证自动处理；当前本地分割器不会编造这些区域的可靠掩码，仍需人工检查或拒绝合成。

服务环境变量：`REPLICATION_VISION_PYTHON`为Python绝对路径；`REPLICATION_SAM_CHECKPOINT`为权重绝对路径；可选`REPLICATION_VISION_PACKAGES`为私有依赖路径、`REPLICATION_VISION_THREADS`为1至4线程。本地子进程使用环境变量白名单，不继承Replicate Token、数据库密码或代理；设置120秒超时、输出上限，不通过Shell执行参数。

## 验收与能力限制

自动测试包括宽鞋底/超出涂抹、小于旧产品、两只鞋、只替换一只、袜子遮挡、背景变化恢复、对齐失败、分割失败、商品不自动合格、鞋底鞋头完整拷贝及掩码职责分离。HTTP集成还覆盖原图下载、失败不得确认、账号隔离、重合成幂等、旧记录不变、重启与GET只读。

验收运行：全量Mock **94/94通过**；类型检查、生产构建、`git diff --check`通过。测试进程禁止真实外部HTTP。分割同时最多运行一个本地子进程；繁忙时明确失败并保留模型原图，用户可稍后仅重新合成，不自动重提收费任务。

现有真实鞋类场景只读取已保存的场景图、模型图与涂抹；在CPU本地进行无费用分割。初次检查背景匹配1510个RANSAC内点，覆盖7个网格，重投影中位误差约0.077工作像素，约14至15秒。但完整产品轮廓未可靠确认；补充点提示后的完整轮廓检查仍失败。**没有生成智能合成候选，没有把此前错误鞋款标记为合格。** 本轮不以降低阈值或套用用户涂抹强行通过该样例。

因此本次验收结论是：数据职责、合成机制、失败保护与模拟场景通过相应测试；**现有复杂鞋图的全自动成功尚未通过验收**。MobileSAM接入可用，但它对本场景的完整商品分割能力不足，仍需进一步验证更合适的本地分割器或更有效的点提示交互。分割正确也不能修复Nano Banana 2已生成错误款式的问题。

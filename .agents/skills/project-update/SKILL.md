# 项目更新交付

适用于本项目每次准备提交并同步 GitHub 的更新。先完成代码或文档修改与适当验证，再执行以下步骤；不扫描全盘，以本次改动、现有总结及必要的项目文件为依据。

1. 更新 `docs/PROJECT_UPDATE_OVERVIEW.md` 中的当前功能、架构、操作及代码逻辑，仅修改受本次变更影响的内容；在版本更新记录最上方增加一条，保留旧记录。记录日期、实际产品版本、改动、验证和部署状态。版本以 `src/data/changelog.json` 或本次明确的版本为准；仅文档或配置更新没有产品版本变化时写明沿用版本，不能虚构或擅自递增版本。相同版本可有多条记录。
2. 不在提交内容中写入其自身尚未存在的提交 SHA；提交后在交付中报告完整 SHA。不得把本地通过、推送 GitHub 说成已部署；线上以实际部署结果为准。
3. 在项目根目录验证变更、提交并同步 GitHub，遵守 `AGENTS.md` 和用户当前要求。禁止未经明确要求调用真实收费模型。
4. 交付时根据实际提交、目标分支和 `deploy/update.sh` 的当前要求给出可复制的服务器更新指令。如该脚本要求部署分支指向确切 SHA，而提交只在其他分支，先给出本机非强制推送该 SHA 到部署分支的指令，再给服务器 fetch、校验 SHA、提取对应版本脚本及执行命令；推送或校验失败即停止。先核实分支与脚本，勿使用猜测的 SHA。说明备份时短暂停服，提醒旧任务可能仍在运行或计费，并以 `DEPLOYMENT_OK <完整SHA>` 判断部署检查是否完成。若变化无需部署，也提供上述指令并说明部署可选，不自行部署。

此技能是 Codex 工作流程，不是 Git 钩子；普通 Git 命令或未遵循本项目约定的工具不会自动触发。
